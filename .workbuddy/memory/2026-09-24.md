## 初始化 oplus.ota 诊断 Hook 仓库

从零搭建（远端仓库原本为空）：

- LSPosed 模块 `com.a23bc.oplus.otatracer`，只监控 `com.oplus.ota`（含 `:ui` 进程）。
- 目的：定位「下载内部测试包」时 `SignVerifyUtils: ecdsaSignPki exception: No installed
  provider supports this key: (null)` → `DownloadException` / `responseCode=2304` 的成因。
  纯诊断，不改 OTA 行为、不绕过签名/完整性/权限/服务端校验。
- 架构：`HookEntry`（入口+包过滤）、`ClassHunter`（类定位）、`OtaLog`（统一 TAG
  `OplusOtaTracer` + 脱敏 + 分块）、`TracerConfig`（目标常量），以及 6 个 tracer：
  SignVerify / GetInfoThread / DownloadException / Response / KeyStore / Prefs / AppLog。
- 类定位三条路：FQCN 猜测 → `ClassLoader#loadClass` 按方法名特征匹配 → 启动 1.5s 后
  dex 扫描兜底（应对混淆）。全部 try-catch，找不到只记一次。
- 日志带 `seq=` 递增序号与 `t=+ms` 相对时间，用于判定 ecdsaSignPki 异常与 2304 的先后。

## 环境/工具坑（本机，影响后续操作）

- **本机 git 无法创建带斜杠的分支 ref**：`refs/heads/feat/xxx` 写不进去（`git commit`
  输出成功但实际未落盘，`git log` 报 no commits）。分支名用不带斜杠的 `tracer`，
  推送时用 refspec `tracer:refs/heads/feat/ota-download-tracer` 得到远端带斜杠分支名。
- **bash 沙箱会丢弃 `.git/objects` 的写入**：commit / push 需用非沙箱模式执行；
  沙箱内 `/tmp` 与非沙箱不互通（`-F /tmp/msg.txt` 在沙箱外读不到）。
- **本机无 Android SDK**，编译走 GitHub Actions（`gh run watch`）。
- CI：`android-actions/setup-android@v3` 在当前 runner 上失败（装已废弃的 `tools` 包）。
  改用 runner 自带的 `/usr/local/lib/android/sdk` + 按需 `sdkmanager --install`
  `platforms;android-34` / `build-tools;34.0.0`；Gradle 8.2 直接下载发行版。
- CI 里有「只读性门禁」：grep `setResult|setThrowable|param.args[n]=`，需排除注释行，
  否则 HookEntry 的注释会误报。
- 产物：debug APK 自带 debug 签名可直接 `adb install`；release 是 unsigned，装不上。

## 真机首次装机：com.oplus.ota:ui 黑屏（已修）

现象：模块启用后 OTA 的 `:ui` 进程起不来，黑屏。日志停在
`[Boot] install complete`（seq=26），之后的 `[AppLog] hook unavailable Log#d ...
(XposedHelpers$ClassNotFoundError)` 是**结果不是原因** —— `android.util.Log`
是 boot class，不可能找不到。

根因：`ClassHunter` hook 了 `ClassLoader#loadClass`，并在回调里对每个被加载的类调
`getDeclaredMethods()` 做方法名匹配。启动期类加载风暴 → 回调内触发嵌套类加载 →
应用 ClassLoader 损坏 → 之后所有 `findClass` 全失败 → UI 进程卡死。

修复（run 35957155803 已过 CI）：
- **删除 loadClass hook**，类加载本身永不 hook；反射只在后台线程做。
- 发现路径改为：FQCN 猜测（启动即解析，会逐条打 `no class xxx`）→ 3s 后关键词 dex
  扫描（后台）→ 9s 后深度扫描（后台，按方法名匹配，60 个/批 sleep 15ms，预算 15s，
  命中 SignVerifyUtils 则跳过）。
- boot class（Log / KeyStore / KeyPairGenerator / KeyFactory / Signature）改用
  `Class` 字面量 hook，不再走 `findClass` 字符串解析。
- SpTracer：廉价 key 过滤提到 `callerIsTargetApp()`（生成栈）之前；LogTracer 限流 25 行/s。
- 加心跳（每 5s 一条 `[Boot] heartbeat left=N rulesHit=[...]`，共 12 条），卡死时
  最后 seq 即卡死点；加 `TracerConfig` 三个开关用于二分定位。

教训：**在 Xposed 里 hook 类加载路径 + 回调内做反射是自毁操作**，会在启动期把宿主
ClassLoader 搞坏，且症状表现为"莫名其妙 ClassNotFoundError + 黑屏"，很难一眼看出。
